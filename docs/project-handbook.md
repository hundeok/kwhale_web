# K-Whale 프로젝트 핸드북

## 1. 한 문장 정의

K-Whale은 공식 공직자 재산공개 원문을 연도별로 보존하고, 재현 가능한
정규화·분류·비교 엔진을 통해 인물·자산·지역의 관계를 탐색하는 공공 데이터
인텔리전스 제품이다.

## 2. 제품 철학

K-Whale의 차별점은 데이터의 양이 아니라 설명 가능한 연결성이다.

```text
공식 원문
→ 보존 파일과 SHA-256
→ 원문 행
→ 정규화 자산
→ 인물·연도·자산 관계
→ 검증 가능한 통계와 인사이트
→ 상세 화면에서 원문까지 역추적
```

외부 서비스는 비교와 참고에 사용할 수 있지만 제품의 런타임 의존성이 되어서는
안 된다. 화면은 전문적이어야 하지만, 보여주기식 숫자나 임의 배분을 사용하지
않는다.

## 4. 연도 모델

- `recent`: 2025년 완결 모집단에 2026년 공개분을 인물별 최신으로 반영한
  기본 탐색 스냅샷
- `2026`, `2025` 등: 해당 기준 연도 스냅샷
- `all`: 모든 연도 합산이 아니라 인물별 최신 레코드를 넓게 탐색하는 뷰
- ALL-TIME 통계: 화면에서 명시적으로 ALL-TIME이라고 표기한 누적 관계 통계

기본 사용자는 최신 정보를 찾으므로 `recent`가 기본이다. 역사 비교는 별도
연도 선택과 인물 상세 타임라인에서 제공한다.

## 5. 메뉴와 역할

| `/` | 대시보드 | 주요 공식 지표, 자산군 리더, K-Whale 알파 엔진 |

| `/analysis/new-assets` | 자산 증가 이벤트 | 신규·증가 자산의 대분류→소분류→원문 행 탐색 |
| `/map` | 전국 자산 지도 | 건물·토지의 공간 분포와 인물·기관 연결 |

| `/securities` | 증권/주식 현황 | 직접 귀속 금액과 보유 관계를 분리한 증권 분석 |
| `/virtual-assets` | 가상자산 | 공식 인물 총액과 코인별 직접 귀속 통계 분리 |
| `/guide` | 이용 가이드 | 숫자·연도·신뢰도 읽는 법 |
| `/about` | 프로젝트 소개 | 방법론·출처·지원·정책 연결 |

## 6. 화면 품질 기준

- 다크 모드 기본, 라이트 모드 독립 검수
- 대제목과 핵심 값은 충분한 크기와 대비 확보
- 보조 텍스트는 정보 밀도를 해치지 않는 최소 크기 유지
- 빈 화면 대신 이유·표본·다음 행동 제공
- 작은 표본에서는 “16개” 같은 고정 문구를 사용하지 않음
- 알파 인사이트는 탐색 신호이며 시장 수익률 예측이 아님을 표시
- 카드 클릭 시 가능한 경우 필터·상세·인물 페이지로 연결

## 7. 핵심 데이터 사례

### 가상자산

김홍수의 OES·도너클 합산 12,523,638,000원은 인물별 공식 가상자산 총액에는
포함되지만 코인별 금액에는 임의 배분하지 않는다.

```text
전체 공식 신고총액
= 코인별 직접 귀속 금액
+ 코인별 미배분 금액
```

### 증권

종목명과 보유자는 파싱하되 복수 종목이 한 행의 평가액을 공유하면 종목별
신고가액에 반복 반영하지 않는다.

### 순자산 비교

증감률과 증감액은 서로 다른 사용자 질문에 답한다.

- 급변 탐지: 작은 기초 자산에서 큰 비율 변화 탐지
- 고액 이동: 절대 금액 기준 큰 변화 탐지

### 지도

상세 주소처럼 보여도 서로 다른 주소가 동일 좌표를 공유하면 대표 좌표로
표시한다. 도서 지역의 실제 좌표를 본토로 보정하지 않는다.

## 8. 외부 참고의 위치

- 리얼시그널: 과거 정제 JSON, 원문 구조와 기능 비교
- Rich Road: 정보 구성과 사용자 동선 비교
- PETI·전자관보·인사혁신처·기관 공보: 공식 근거

외부 서비스의 문구·브랜드·레이아웃을 복제하지 않는다. 좋은 문제 정의를
참고하되 K-Whale의 방법론과 시각 언어로 재설계한다.

## 9. 장기 제품 방향

최종 목표는 인물 페이지뿐 아니라 주식 종목, 코인, 부동산 지역, 기관, 자산
유형 모두가 고유 상세 페이지를 갖는 엔티티 그래프다.

```text
인물 ↔ 연도 ↔ 원문 신고
  ↕          ↕
기관       자산 행
             ↕
주식·코인·지역·부동산·차량·채권
```

이 단계에서는 이름 문자열이 아니라 안정적인 엔티티 ID, 별칭 테이블, 관계
신뢰도와 원문 계보가 필수다.
